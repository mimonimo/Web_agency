# 결과물에서 반복되는 결함 — 관찰 기록

로컬 모델(`gpt-oss:120b`)로 사이클을 돌리며 **실제로 나온** 결함만 적는다.
추측은 안 적는다. 각 항목에 **왜 생기는지 / 지금 무엇으로 막는지 / 아직 못 막은 것**을 쓴다.

> 이 문서의 쓸모: 지시문·검사기를 고칠 때 여기부터 본다.
> 그리고 "AI 가 만들면 이렇게 된다" 를 학생에게 보여 주는 자료다.

## 1. CSS 변수를 쓰는데 정의가 없다 ★★★

**증상.** `color: var(--color-text)` 는 잔뜩 있는데 `:root` 에 그 변수가 없다.
브라우저는 **아무 말 없이** 기본값을 쓴다. 색이 하나도 안 먹은 화면이 나온다.
"CSS 가 깨졌다" 고 느끼는 것의 절반이 이것이다.

**왜.** 모델이 디자인 토큰을 "읽었다" 고 생각하고 변수 이름만 가져다 쓴다.
정의를 옮겨 적는 단계를 건너뛴다.

**막는 것.** `checks._frontend` 가 `var(--x)` 로 **쓰는 변수**와
`--x:` 로 **정의된 변수**의 차집합을 낸다. 하나라도 있으면 미달 → 자동 재작업.

```python
used = set(re.findall(r"var\((--[a-z0-9-]+)", css))
defined = set(re.findall(r"(--[a-z0-9-]+)\s*:", css))
orphan = sorted(used - defined)
```

## 2. 토큰을 별도 `.css` 로 빼고 `@import` 를 빠뜨린다 ★★★ — **아직 완전히 못 막음**

**증상.** `design-tokens.css` 를 따로 만들고 `style.css` 에서 불러오지 않는다.
결과는 1번과 같다. 색이 통째로 안 먹는다.

**실측.** 사이클 #1 의 프론트엔드 산출물에 지금도 `design-tokens.css` 가 있다.
`style.css` 안에 `:root` 정의를 함께 넣어 두어서 화면은 살았지만,
**두 곳에 같은 토큰이 있는 상태**다. 하나를 고치면 다른 하나가 남는다.

**막는 것(부분).** `_quality.md`·`implement.md`·`gate.md` 세 곳에
"토큰은 `style.css` 맨 위 `:root` 에 직접 써라. 파일을 나누지 마라" 를 넣었다.
1번 검사가 결과적으로 잡아 주긴 한다 (정의가 없으면 걸린다).

**아직 못 막은 것.** 정의를 양쪽에 **중복**해 두면 검사를 통과한다.
→ 할 일: `output/` 에 `design-tokens.css` 가 있는데 `style.css` 에
`@import` 가 없으면 미달로 잡는 검사 추가.

## 3. 하위 폴더를 두 겹 만든다 ★★★

**증상.** `output/frontend/frontend/index.html`.
`<link href="./style.css">` 가 상위의 `style.css` 를 못 찾아 **스타일이 통째로 빠진다.**

**왜.** 노드 어댑터가 역할별 작업 디렉터리를 만드는데, 모델이 그 안에
자기 역할 이름으로 폴더를 또 만든다.

**막는 것.** `checks._frontend` 가 `index.html` 이 최상위가 아닌 곳에 있으면 미달.
실측: 사이클 #1 에서 이 검사가 걸려 자동 재작업이 돌았다.

```
hq→frontend  S5 완료 조건 13/15 — 미달 2건, 다시 시킨다
             미달: label 이 입력 수를 덮음 (6/7), output/ 바로 아래 평평하게 둠
```

## 4. 남의 역할 파일을 만든다 ★★★

**증상.** DBA 가 `seed.sql` 만 내야 하는데
`index.html`·`app.js`·`style.css` 까지 통째로 만들어 올렸다.
같은 파일이 두 벌 생기면 어느 것이 진짜인지 아무도 모른다.

**왜.** 모델이 "도와주려고" 한다. 참고 자료로 받은 화면 목록을 보고
자기가 만들어야 한다고 판단한다.

**막는 것.** 네 겹.
1. `runner._save_artifacts` — 같은 단계 다른 역할의 선언 산출물은 **저장하지 않는다**
2. `checks._no_web_files` — DBA·백엔드가 html/css 를 내면 미달
3. `roles.yaml`·기준선 AGENT.md·`_quality.md` 에 금지 문구
4. 사이트 목록에서 프론트엔드 산출물만 표시

## 5. 참고 자료가 산출물로 되돌아온다 ★★

**증상.** DBA 산출물에 `SCREENS.md`·`design-tokens.json` 이 들어 있다.
읽으라고 준 파일이 만들었다고 올라온다.

**왜.** 어댑터가 참고 자료를 작업 디렉터리에 내려놓고 일한다.
끝나면 디렉터리 안의 파일을 전부 수집한다.

**막는 것.** `_save_artifacts` 가 보낸 참고 자료와 **내용을 대조**해
같으면 제외한다. 제외한 사실과 이유는 콘솔에 남긴다.

---

## 6. `<label for>` 가 입력 수보다 적다 ★★

**증상.** `input` 7개인데 `label for` 6개. 하나가 이름 없는 입력칸이 된다.
스크린리더로는 무엇을 넣는 칸인지 알 수 없다.

**막는 것.** `checks` 가 개수를 센다. 실측으로 이 검사가 재작업을 걸었다.

---

## 7. viewport·시맨틱 태그 누락 ★★★

**증상.** 첫 사이클 결과물(`showcase/v1-before`)은
viewport 없음, `<header>/<nav>/<main>/<section>/<footer>` **0개**,
전부 `<div>`. 휴대폰에서 글자가 깨알같이 작게 나온다.

**막는 것.** `checks` + `_quality.md`. 개선 후(`v2-after`) 5/5 로 올라갔다.

---

## 8. 기본 파랑/초록으로 도망간다 ★★

**증상.** 주문서에 "따뜻하고 아날로그한" 이라고 적혀 있는데
버튼이 `#4CAF50`(머티리얼 초록). 어느 프로젝트에나 있는 화면이 된다.

**막는 것.** `checks._designer` 가 `#4CAF50`·`#0066CC` 등을 찾으면 미달.
기준선 AGENT.md 의 '금지' 에 "무난한 회색·파랑으로 도망가지 않는다".

---

## 9. `<br>` 로 폼을 배치한다 ★★

**증상.** `v1-before` 에 `<br>` 4개로 줄바꿈한 폼. 폭이 바뀌면 무너진다.

**막는 것.** `checks` 가 `<br>` 3개 이상이면 미달 + flex/grid 사용을 확인.

---

## 10. `npm install` 을 실행한다 ★★★ — 부분

**증상.** 첫 리허설에서 `node_modules` 663개 파일이 산출물로 올라왔다.
교실에는 인터넷이 없으므로 당일이면 그냥 실패한다.

**막는 것.** 어댑터 `SKIP_DIRS` + 최대 60개 상한, 지시문 3곳에 금지 문구.

**아직 못 막은 것.** 노드에 인터넷이 있으면 **실행 자체는 된다** (시간만 버린다).
→ 수업 당일 노드 인터넷을 끊어 두는 것이 확실하다.

---

## 11. 판정서 첫 줄 형식 위반 ★★

**증상.** `# 검수 결과` 로 시작하고 판정은 세 줄 뒤에 나온다.
HQ 가 첫 줄만 읽으므로 **판정을 못 읽고 통과로 처리**한다.

**막는 것.** `checks._verdict` 가 첫 줄이 정확히 `판정: 통과|반려` 인지 본다.
읽기는 여전히 관대하게 한다 — 못 읽으면 통과로 본다.
판정을 못 했다고 수업을 멈춰 세울 수는 없기 때문이다.

---

## 12. 반려 사유가 제목뿐 ★★

**증상.** `판정: 반려` 다음 줄이 `## 이유 및 개선 방안`.
HQ 가 그 줄을 사유로 가져가 티켓 제목이 `## 이유 및 개선 방안` 이 된다.
아무 정보가 없다.

**막는 것.** 사유 추출 시 마크다운 제목·코드펜스를 건너뛰고
실질 내용 3줄을 이어 붙인다.

---

## 13. 프롬프트가 커지면 응답이 멈춘다 ★★★

**증상.** 게이트에 심사 파일 8종을 붙였더니 프롬프트가 **26KB**.
그 뒤 S5 재작업이 진행되지 않고 정체했다.

**막는 것.** 어댑터가 참고 자료를 파일당 4000자 / 전체 14000자로 자른다.
자른 파일은 제목에 `(앞부분만)` 이라고 밝힌다 —
조용히 자르면 "이게 전부" 라고 오해한다.

> **참고 자료를 안 주면 지어내고, 너무 주면 멈춘다.**
> `inputs` 를 늘릴 때는 프롬프트 크기를 같이 봐야 한다.

---

## 14. 참고 자료 미전달 → 통째로 지어낸다 ★★★

**증상(최악).** 프론트엔드가 화면 목록도 디자인 토큰도 **못 본 채** 사이트를 만들었다.
품질 10/19 (53점).

**왜.** `pipeline.yaml` 의 `inputs: [SRS.md]` 를 그대로 URL 로 넘겼는데
실제 파일은 `runs/1/S2/output/SRS.md` 에 있었다. **전부 404.**
그리고 아무도 그 사실을 몰랐다.

**막는 것.** `runner.resolve_inputs()` 가 이름 → 실제 경로를 찾아 넘긴다.
어댑터는 참고 자료를 **하나도 못 받으면 HQ 에 경고를 미러링**한다.
다시 조용히 실패하지 않게.

고친 뒤 같은 주문으로 19/19 (100점).

## 이 결함들이 다시 안 나오게 하는 방법

지시문에 "하지 마라" 를 적는 것만으로는 **안 막힌다.** 실측으로 확인했다.
막히는 것은 **검사 → 실패 목록 → 재실행** 루프뿐이다.

```
지시(프롬프트) → 실행 → ★검사(checks.py) → 미달이면 사유를 붙여 재실행
```

새 결함을 발견하면 순서는 이렇다.

1. 여기(이 문서)에 증상과 재현을 적는다
2. `checks.py` 에 기계 검사를 넣는다 — **고치는 방법(`fix`)을 반드시 함께**
3. `roles.yaml` 의 `forbid` 와 기준선 AGENT.md 에 문구를 넣는다
4. `core/tests/test_roles.py` 에 그 검사가 동작하는지 테스트를 넣는다
