# SRS — 별빛공방 원데이 클래스 예약

> S2 기획. 주문서와 `SOW.md` 를 읽고 **테스트할 수 있는 문장**으로 옮겼다.
> 수용 기준은 QA 가 그대로 실행할 수 있어야 한다.

## F-1 클래스 목록

- 설명: 방문자가 지금 신청할 수 있는 클래스를 한 화면에서 본다.
- 수용 기준
  - [ ] 클래스 4개(물레 체험 / 손으로 빚는 컵 / 유약 놀이 / 커플 클래스)가 모두 보인다
  - [ ] 각 카드에 이름·가격·소요시간·정원이 함께 보인다
  - [ ] 가격은 `45,000원` 처럼 세 자리마다 쉼표를 찍는다
  - [ ] 카드를 누르면 그 클래스의 상세로 이동한다
  - [ ] 휴대폰 폭(390px)에서 카드가 한 줄에 하나씩 세로로 쌓인다

## F-2 클래스 상세

- 설명: 무엇을 만드는지, 얼마나 걸리는지, 무엇을 준비해야 하는지 본다.
- 수용 기준
  - [ ] 목록에서 고른 클래스의 이름·가격·소요시간·정원·설명이 보인다
  - [ ] 준비물 안내가 있다
  - [ ] [이 클래스 예약하기] 를 누르면 예약 화면으로 가고, **그 클래스가 미리 골라져 있다**
  - [ ] [목록으로] 로 돌아갈 수 있다

## F-3 예약

- 설명: 클래스·날짜·시간대·인원·연락처를 넣어 예약한다.
- 수용 기준
  - [ ] 클래스·날짜·시간대·이름·연락처를 모두 채우기 전에는 [예약하기]가 눌리지 않는다
  - [ ] 날짜는 **오늘 이후**만 고를 수 있다
  - [ ] **월요일은 고를 수 없다** (휴무). 고르면 "월요일은 휴무입니다" 를 보여준다
  - [ ] 시간대는 10:00 / 14:00 / 19:00 세 개다
  - [ ] 인원이 그 클래스 정원을 넘으면 "정원은 N명입니다" 를 보여주고 접수하지 않는다
  - [ ] 연락처가 숫자 9자리 미만이면 "연락처를 확인해 주세요" 를 보여준다
  - [ ] 접수되면 `BB-20260812-001` 형식의 예약번호가 화면에 보인다
  - [ ] 접수된 예약은 **새로고침 후에도** 조회된다

## F-4 예약 확인

- 설명: 예약번호로 내 예약을 조회한다.
- 수용 기준
  - [ ] 예약번호를 넣고 [조회] 하면 클래스·날짜·시간·인원·이름이 보인다
  - [ ] 없는 번호면 "그런 예약번호가 없습니다" 를 보여준다
  - [ ] 방금 예약한 사람은 번호를 **다시 입력하지 않아도** 바로 보인다

## F-5 문의

- 설명: 간단한 질문을 남긴다.
- 수용 기준
  - [ ] 이름·연락처·내용을 넣고 [보내기] 하면 접수 확인 문구가 보인다
  - [ ] 내용이 10자 미만이면 "문의 내용을 조금 더 적어 주세요" 를 보여준다
  - [ ] 보낸 문의는 화면 아래 목록에 쌓인다

## 가정한 것

- 예약 저장은 **브라우저 안(localStorage)** 에 한다. 서버 DB 연동은 이번 범위 밖이므로
  `server.js` 는 계약대로 동작하는 참조 구현만 둔다.
- 정원 초과 판정은 **같은 날짜·같은 시간대·같은 클래스**의 이미 접수된 인원 합으로 한다.
- 공휴일은 다루지 않는다. 월요일 휴무만 반영한다.

## 주문서와 충돌한 것

없음. 주문서의 "안 해도 되는 것"(결제·회원가입·후기)은 모두 제외했다.
