판정: 통과

## 확인한 항목

| 항목 | 결과 |
|---|---|
| 비밀번호 저장 방식 | **해당 없음** — 회원가입이 범위 밖(SOW 제외 2). `schema.sql` 에 password 계열 컬럼 없음 |
| 입력 검증 위치 | ✅ **서버에서도** 한다. `server.js` `validateBooking()` 이 날짜·요일·시간대·인원·정원·연락처를 전부 재확인 |
| 에러 메시지 노출 | ✅ `catch` 에서 `console.error` 로만 남기고 응답은 `{"ok":false,"error":"요청을 처리하지 못했습니다"}` |
| 하드코딩된 비밀값 | ✅ 없음. `grep -iE "password|secret|token|api[-_]?key"` 결과 0건 |
| 외부 리소스 참조 | ✅ 없음. `http(s)://` 참조 0건 (CDN·폰트·이미지 모두 없음) |

## 추가로 본 것

| | |
|---|---|
| 경로 탈출 | ✅ `serveStatic()` 이 `path.normalize` 후 `startsWith(ROOT)` 확인. `/../../etc/passwd` 차단 |
| 요청 크기 | ✅ 본문 8KB 초과 시 `req.destroy()` — 대용량 POST 로 메모리를 밀어붙이는 것을 막는다 |
| XSS | ✅ 화면에 넣는 모든 사용자 입력을 `esc()` 로 이스케이프. `innerHTML` 에 원문을 직접 넣는 곳 없음 |
| SQL 인젝션 | 해당 없음 — 이번 구현은 쿼리를 만들지 않는다. `schema.sql` 적용 시 **바인딩 파라미터 필수**로 남긴다 |
| 개인정보 | ⚠️ 이름·연락처를 localStorage 에 평문 보관. 공용 PC 에서는 남는다 |

## 위험으로 기록 (이번 범위에서 반려하지 않음)

1. **연락처 평문 보관** — 공용 기기 사용 시 다음 사람이 볼 수 있다.
   실서비스 전환 시 서버 저장 + 조회 시 마스킹(`010-****-8890`)을 권한다.
2. **HTTPS 미적용** — 폐쇄망 전제. 외부 공개 시 필수다.
3. **API 에 인증이 없다** — 누구나 `/api/bookings` 로 접수할 수 있다.
   현재 범위(공방 내부·폐쇄망)에서는 허용. 공개 시 최소한 rate limit 필요.

HTTPS·방화벽은 이번 사이클의 산출물이 아니므로 반려 사유로 삼지 않는다.
