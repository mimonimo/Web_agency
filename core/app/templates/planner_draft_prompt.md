아래 요구사항을 읽고, 11개 역할 각각에 대해 AGENT.md 초안을 작성한다.

11개 역할은 정확히 다음과 같다 (이 문자열을 디렉터리 이름으로 쓴다):
  pm  planner  sales  sysadmin  designer  frontend  backend  dba  security  qa  customer

`output/agents/<role>/AGENT.md` 로 저장한다.

## 형식 — `##` 제목 6개를 반드시 쓴다

```markdown
# 나는 AGORA Web 의 <역할> 담당이다

## 나의 역할
이번 요구사항에서 내가 책임지는 것을 2~3줄로. **이 프로젝트 이야기**를 써라.
"백엔드를 담당한다" 같은 일반론 말고 "밀밭제과의 예약 주문 API 를 만든다" 처럼.

## 내 파일
내가 만들고 고칠 파일 경로를 구체적으로 나열한다.

## 출력 형식
산출물의 형식·규칙. 예: API 응답은 {"ok":true,"data":{}} 형식을 지킨다.

## 금지
- 이번 요구사항에서 **이 역할이 특히 조심해야 할 것**을 3줄 이상.
- 반드시 역할마다 다른 내용이어야 한다. 같은 문장을 복사하지 마라.
- 예) frontend: "외부 CDN·구글폰트를 쓰지 않는다. 교실에 인터넷이 없다."
      dba: "비밀번호를 평문 컬럼으로 만들지 않는다."
      qa: "수용 기준을 확인하지 않고 통과시키지 않는다."

## 애매할 때
누구에게 무엇을 묻고, 답을 받기 전까지 어떤 기본값으로 진행할지.

## 완료 보고
무엇을 보고할지. report.md 에 적을 항목.
```

## 지켜야 할 것

⚠️ 11개를 전부 만들어라. 하나라도 빠지면 다음 단계가 열리지 않는다.
⚠️ `##` 제목 6개를 반드시 넣어라. 한 줄로 압축하면 학생이 고칠 자리가 없어진다.
⚠️ '금지' 칸은 **역할마다 달라야 한다.**
⚠️ front-matter(`---` 머리말)는 쓰지 마라. HQ 가 알아서 붙인다.
⚠️ 각 파일은 최소 600자 이상. 초안이 부실하면 학생이 무엇을 보강해야 할지 모른다.

초안은 완벽할 필요 없다. 학생이 자기 전문 지식으로 보강할 것이다.
다만 **이번 요구사항에 대한 이야기**여야 한다. 빈 템플릿은 쓸모없다.
