## `SRS.md` — 요구사항 명세

주문서의 '필요 기능' **하나하나**를 항목으로 만들고, 각각에 **수용 기준**을 붙인다.

```markdown
## F-1 로그인
- 설명: 고객이 이메일과 비밀번호로 로그인한다.
- 수용 기준
  - [ ] 잘못된 비밀번호면 "이메일 또는 비밀번호가 올바르지 않습니다" 를 보여준다
  - [ ] 비밀번호는 평문으로 저장하지 않는다
  - [ ] 로그인 후 이전에 보던 화면으로 돌아간다
```

수용 기준은 **QA 가 그대로 테스트할 수 있을 만큼** 구체적이어야 한다.
"잘 동작한다" 같은 문장은 쓸모없다.

## `SCREENS.md` — 화면 목록

필요한 화면을 빠짐없이 적고, 각 화면마다
**무엇이 보이는지 / 무엇을 할 수 있는지 / 어디로 이동하는지** 를 쓴다.

⚠️ 여기 적은 화면 수가 구현 단계의 목표가 된다.
주문서에 없는 화면을 늘리지 말고, 필요한 화면을 빠뜨리지도 마라.
