## 역할별 「이번 프로젝트」 칸을 쓴다

각 역할의 AGENT.md 는 **이미 만들어져 있다.** 역할이 무엇인지, 무엇을 금지하는지,
어떻게 보고하는지는 전부 정해져 있으니 다시 쓰지 마라.

너가 채울 것은 **한 칸뿐**이다 — 「이번 프로젝트에서 이 역할이 맡는 것」.

## 무엇을 쓰나

주문서와 `SRS.md`·`SCREENS.md` 를 읽고, 그 역할에게 **이번 주문의 구체적인 일**을 준다.

```markdown
- **맡는 것**: 밀밭제과 예약 주문 사이트의 화면 5개(홈·상세·주문·주문확인·문의)를 만든다.
- **꼭 지킬 것**: 주문서의 "따뜻하고 아날로그한" 톤 — 디자이너가 준 금빛/크림 토큰을 그대로 쓴다.
- **이번에 조심할 것**: 수령일 입력은 오늘 이후만 고를 수 있어야 한다 (SRS F-1).
- **연락할 사람**: 응답 형식이 다르면 backend, 색이 모자라면 designer.
```

네 줄이면 충분하다. 길게 쓰지 마라.

## 규칙

- **이번 주문의 고유명사를 써라.** 회사명·상품명·화면 이름을 그대로.
  "웹사이트를 만든다" 는 어느 프로젝트에나 해당돼서 쓸모가 없다.
- **역할마다 내용이 달라야 한다.** 같은 문장을 복사하지 마라.
- **주문서에 없는 것을 지어내지 마라.** 가격·연락처·기능을 만들어 내면 뒤가 다 틀어진다.
- **120자 이상.** 한 줄짜리는 반려된다.
- **`##` 제목을 넣지 마라.** 본문만 쓴다. HQ 가 알맞은 자리에 끼워 넣는다.
- **front-matter(`---` 머리말)를 쓰지 마라.**
