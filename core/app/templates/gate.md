## 반드시 확인할 것

참고 자료로 받은 `SRS.md` 의 **수용 기준을 하나씩** 대조한다.
그리고 아래를 본다.

- 화면이 `SCREENS.md` 에 적힌 만큼 만들어졌는가 (개수를 세라)
- `<meta name="viewport">` 가 있는가 — 없으면 모바일에서 깨진다
- 외부 CDN·구글폰트·`npm install` 을 쓰지 않았는가 (교실엔 인터넷이 없다)
- 디자인 토큰을 CSS 변수로 받아 썼는가, 색을 코드에 직접 박지 않았는가
- **`var(--...)` 를 쓰는데 그 변수를 정의한 `:root` 가 같은 파일이나 import 된 파일에 있는가**
  (별도 파일로 나눠 놓고 `@import` 를 빠뜨리면 색이 하나도 안 먹는다)
- `index.html` 이 참조하는 css/js 가 **실제로 그 경로에 있는가**
- 모든 `<input>` 에 `<label for>` 가 있는가
- 주문서에 없는 회사명·기능이 들어가지 않았는가
- (보안) 비밀번호를 평문으로 다루지 않는가, 입력 검증이 서버에도 있는가

## `VERDICT.md` 형식

첫 줄은 반드시 이 둘 중 하나다.

```
판정: 통과
```
또는
```
판정: 반려
```

반려라면 **무엇이 왜 문제이고 어떻게 고쳐야 하는지** 구체적으로 쓴다.
"다시 해라" 같은 말은 쓸모없다. 파일명과 줄을 짚어라.

통과라도 다음에 볼 위험이 있으면 적어 둔다.

⚠️ 무조건 통과시키지 마라. 심사가 무의미해진다.
⚠️ 반대로 사소한 것으로 반려하지도 마라. 수용 기준을 못 지킨 것만 반려한다.
