# AGORA Web — 11명의 AI 에이전트가 웹 에이전시처럼 일한다

고등학교 **AI 에이전트 PBL 수업**을 위한 중앙 오케스트레이터.

주문서 한 장을 넣으면 영업 → 기획 → 설계 → 구현 → QA·보안·검수 → 배포 → 운영이
실제로 돌아가고, **사람이 원하는 지점에서 멈추고·고치고·재개하고·처음부터 다시** 할 수 있다.

학생이 배우는 것은 코드가 아니다. **지시문(AGENT.md) 한 줄이 결과를 어떻게 바꾸는가**다.

```
DGX 11대 · 각자 로컬 Ollama(gpt-oss:120b) · 인터넷 없이 교실에서 완결
```

## 왜 이렇게 만들었나 — 세 가지 결정

### 1. 지시문의 뼈대는 사람이 쓴다

로컬 모델(`gpt-oss:120b`)에게 "11개 역할 지시문을 알아서 잘 써라" 를 시키면
빈 템플릿이나 서로 똑같은 문장이 나온다. **실제로 그랬다.**

그래서 구조와 품질 기준은 사람이 확정하고 (`agents/<role>/AGENT.md`),
모델에게는 **"이번 주문에서 이 역할이 맡는 일" 네 줄만** 맡긴다.
짧고 구체적인 일은 작은 모델도 해낸다.

> 이 구조는 모델을 바꿔도 유지된다. Claude 를 붙이든 더 큰 오픈 모델을 붙이든,
> 품질의 바닥은 기준선이 잡는다. 좋은 모델은 그 위에서 더 잘할 뿐이다.

### 2. 부탁하지 않고 검사한다

"viewport 를 넣어라" 라고 **부탁**하는 것과, 넣었는지 **확인하고** 안 넣었으면
무엇이 틀렸는지 알려 주며 다시 시키는 것은 다른 일이다.

```
지시 → 실행 → ★검사(checks.py) → 미달이면 실패 목록을 붙여 재실행 → 게이트
```

기계가 볼 수 있는 것(형식·존재·수치)은 기계가 본다.
의미는 QA·보안·검수 게이트 에이전트가 본다.

### 3. 사람이 언제든 끼어들 수 있다

```
/agent.html?role=designer  →  "버튼 모서리를 더 둥글게" 한 줄
                           →  다음 실행 프롬프트 맨 뒤에 ★최우선으로 붙는다
/review.html               →  프리뷰를 보면서 한 줄 → 「지금 고치기」
                           →  지시 꽂기 + 일시정지 + 재실행이 한 번에 (2~5분)
```

## 빠르게 돌려 보기

```bash
git clone https://github.com/mimonimo/Web_agency.git agora && cd agora
python3 -m venv .venv && .venv/bin/pip install -r core/requirements.txt

cp .env.example .env         # EXECUTOR=sim  ← 노드 없이 흐름만 확인
./ops/dev.sh start           # http://localhost:8000
```

`EXECUTOR=sim` 은 HQ 안에서 산출물을 흉내낸다 (한 단계 1~4초).
실제 노드로 돌리려면 `.env` 를 `EXECUTOR=a2a` 로 바꾸고
`node/bootstrap-node.sh` 로 어댑터를 배포한다.

```bash
make test              # 상태기계 38건 + 역할카탈로그 89건 + E2E 흐름
./ops/acceptance.sh    # 전체 인수 111건
./ops/rehearsal.sh     # 실제 노드로 한 사이클 완주
```

## 역할 11개

| 노드 | 역할 | 하는 일 |
|---|---|---|
| dgx-02 | 기획 planner | 애매한 말을 **테스트할 수 있는 문장**으로 바꾼다 |
| dgx-03 | 영업 sales | 무엇을 사고 **무엇을 안 사는지** 못 박는다 |
| dgx-04 | 인프라 sysadmin | 만든 것이 **다른 컴퓨터에서도** 뜨게 한다 |
| dgx-05 | 디자인 designer | 어떤 느낌이어야 하는지를 **숫자로** 바꾼다 |
| dgx-06 | 프론트엔드 frontend | 화면 목록을 **실제로 열리는 페이지**로 만든다 |
| dgx-07 | 백엔드 backend | 화면이 필요한 데이터를 **약속한 형식대로** 준다 |
| dgx-08 | DB dba | 데이터가 **나중에 꼬이지 않게** 구조를 잡는다 |
| dgx-09 | 보안 security | **사고가 날 지점**을 먼저 찾아낸다 |
| dgx-10 | QA qa | 수용 기준을 **하나씩 대조해** 판정한다 |
| dgx-11 | 고객 customer | 만든 사람이 아니라 **쓰는 사람의 눈**으로 본다 |
| dgx-12 | 관리 pm | 사이클이 **어디서 왜 멈췄는지** 알아내고 없앤다 |

각 역할의 목표·완료조건·금지는 [`core/app/roles.yaml`](core/app/roles.yaml) 한 파일에 있다.
코드가 아니라 데이터라서 수업 중에 고칠 수 있다.
