# `agents/` — 역할별 AGENT.md 기준선

여기 있는 11개 파일은 **기준선(baseline)** 이다. 수업 중에 쓰는 작업본이 아니다.

| | 기준선 (여기) | 작업본 |
|---|---|---|
| 경로 | `agents/<role>/AGENT.md` | `repo/project-001/agents/<role>/AGENT.md` |
| 누가 쓰나 | 사람(Claude Code)이 미리 써 둔다 | S2 기획이 프로젝트 내용을 붙여 만든다 |
| 언제 바뀌나 | 커리큘럼을 고칠 때 | 사이클마다 |
| git | 추적한다 | 추적하지 않는다 (`.gitignore`) |

## 왜 기준선을 사람이 쓰는가

교실의 로컬 모델(`gpt-oss:120b`)에게 "11개 역할의 지시문을 알아서 잘 써라" 를 시키면
빈 템플릿이나 서로 똑같은 문장이 나온다. 실제로 그랬다.

그래서 **구조와 품질 기준은 사람이 확정**하고, 모델에게는
**"이번 프로젝트에서는 무엇을 맡는가" 한 칸만** 채우게 한다.
짧고 구체적인 일은 작은 모델도 해낸다.

이 설계는 모델을 바꿔도 유지된다 — Claude 를 붙이든 더 큰 오픈 모델을 붙이든,
결과물 품질의 바닥은 이 파일들이 잡는다. 좋은 모델은 그 위에서 더 잘할 뿐이다.

## 구조

각 파일은 다음 순서를 지킨다. 순서와 제목은 코드가 파싱한다 (`runner.spec_ok`).

```
# 나는 AGORA Web 의 <역할> 담당이다
## 나의 목표          ← 왜 이 역할이 있는가
## 담당 단계          ← 언제 일하나 / 무엇을 읽고 무엇을 내나
## 나의 역할          ← 책임 범위
## 내 파일            ← 내가 만드는 파일 경로
## 출력 형식          ← 형식 규칙
## 완료 조건          ← ★ 기계가 검사한다 (core/app/checks.py)
## 금지               ← 이 역할이 특히 저지르는 실수
## 애매할 때          ← 막혔을 때 누구에게 무엇을 묻나
## 완료 보고          ← report.md 에 적을 것
## 이번 프로젝트      ← ★ 여기만 기획(S2)이 채운다
```

## 고치는 방법

- **역할의 목표·완료조건을 바꾼다** → `core/app/roles.yaml` 을 고치고
  `python ops/sync-agents.py` 로 이 파일들을 다시 만든다.
- **문장을 다듬는다** → 이 파일을 직접 고친다. 다음 사이클부터 적용된다.
- **학생이 고친다** → 여기가 아니라 `/edit.html` 에서 작업본을 고친다.
  기준선은 학생 손이 닿지 않는다. 그래야 "고친 것 vs 원본" 비교가 가능하다.
