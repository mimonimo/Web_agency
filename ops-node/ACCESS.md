## 포트 현황 (2026-07-28)

| 포트 | 용도 | dgx-01~11 | dgx-12 (PM·HQ) |
|---|---|---|---|
| **8022** | SSH | ✅ 열림 | ✅ 열림 |
| **8000** | HQ 웹서비스 (픽셀 오피스·주문·API) | 해당 없음 | ⚠️ ufw 로 막힘 → 아래 조치 |
| **11434** | Ollama (`gpt-oss:120b`) | ✅ 전부 열림 | ⚠️ 127.0.0.1 만 → 아래 조치 |

dgx-01(10.0.0.51)도 살아 있고 11434 가 이미 열려 있다. 역할 배정에는 포함돼 있지 않다.

### dgx-12 에서 8000·11434 를 열려면 (root 필요, 1회)

```bash
sudo bash ~/agora-ops/expose-dgx12.sh
```

멱등하다. Ollama 를 `0.0.0.0:11434` 로 바꾸고 ufw 에 8022·8000·11434 를 허용한다.
되돌리려면 `sudo ufw delete allow 8000/tcp` 등.

> ⚠️ Ollama 와 HQ 에는 **인증이 없다.** 교실 L2 안에서만 열리는 것을 전제로 한다.
> 외부망에 노출된 대역이라면 아래 SSH 터널만 쓰는 편이 안전하다.

노드(dgx-02~11)는 `~/agora-ops/expose-ollama.sh` 로 이미 처리했다 (ufw 비활성이라 바인딩만 변경).

# PM 화면 접속 방법

HQ 는 dgx-12(10.0.0.62)의 **8000 포트**에서 돈다. 서버는 `0.0.0.0:8000` 을 정상적으로
듣고 있지만 **ufw 방화벽이 8022(SSH)만 열어 두어** 밖에서 8000 이 막혀 있다.

```
LISTEN 0.0.0.0:8000        ← 서버는 듣고 있음
10.0.0.62:8000 → 200     ← 서버 자신에서는 열림
ufw: active                ← 방화벽이 외부 차단
```

---

## 방법 1 — SSH 터널 (권장 · sudo 불필요 · 즉시)

호스트 PC 터미널에서:

```bash
ssh -p 8022 -L 8000:127.0.0.1:8000 dgx-12@10.0.0.62
```

- 브라우저에서 **http://localhost:8000** → PM 화면
- **같은 창에서 셸도 그대로 쓸 수 있다.** SSH 를 포기하지 않는다.
- 창을 닫으면 터널도 닫힌다.

셸 없이 터널만 백그라운드로 띄우고 SSH 는 따로 쓰고 싶다면:

```bash
ssh -p 8022 -f -N -L 8000:127.0.0.1:8000 dgx-12@10.0.0.62   # 터널만
ssh -p 8022 dgx-12@10.0.0.62                                 # 셸은 따로
```

터널 정리:

```bash
pkill -f "8000:127.0.0.1:8000"
```

> Windows 는 PowerShell 의 기본 `ssh` 로 같은 명령이 그대로 된다.
> PuTTY 라면 Connection → SSH → Tunnels 에서
> Source port `8000`, Destination `127.0.0.1:8000`, Local 로 추가.

## 방법 2 — 방화벽 열기 (교실용 · sudo 필요 · 1회)

수업 중에는 프로젝터·학생 PC 등 여러 대가 봐야 하므로 매번 터널을 파는 건 번거롭다.
dgx-12 에서 한 번만:

```bash
sudo ufw allow 8000/tcp
```

- 그 뒤로는 **http://10.0.0.62:8000** 으로 누구나 바로 접속
- **SSH(8022)에는 영향 없다.** 기존 규칙은 그대로 남는다
- 되돌리려면 `sudo ufw delete allow 8000/tcp`

교실 L2 안에서만 열리는 것이므로 위험하지 않다.
다만 HQ 에는 인증이 없으니 **외부망에 노출된 대역이라면 방법 1 을 쓰는 게 맞다.**
